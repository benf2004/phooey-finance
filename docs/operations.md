# Operations and recovery

## Imports and exports

Preview CSV mapping before import. Duplicate candidates are highlighted rather than automatically discarded: identical transactions can be legitimate. Submitted rows retain import-specific idempotency keys. If a job fails, use Retry in Settings, or submit the identical file/mapping/skipped rows again to resume. Completed imports are recognized and not reinserted.

Browser CSV downloads stream directly; MCP exports run as jobs and are retained in R2 temporarily. Never make the R2 bucket public. Configure lifecycle expiry for `exports/` (one day) and abandoned `sync/` staging (seven days), leaving `imports/` intact for recovery.

## Portable backups

Settings → Full backup downloads accounts, transactions, splits, categories, rules, balance history, audit records and tax plans/payments. Tokens, sessions, bank credentials and encryption keys are excluded. Incomplete imports must finish or resume before backup, preventing partial imports from becoming irrecoverable after restore.

Restore the JSON into a fresh, disconnected deployment with no transactions or active jobs. Default categories are replaced. Validation and insertion are atomic: failure leaves the ledger unchanged. Reconnect SimpleFIN and authorize MCP clients afterward. Do not reconnect a bank until restore completes.

## Larger SQL backups

For ledgers exceeding the portable restore limit, use the provided SQL exporter after all imports finish. It exports the same business tables, excluding credentials and the FTS virtual table. Store financial backups privately.

```sh
node scripts/backup-sql.mjs
# Optional local development backup:
node scripts/backup-sql.mjs --local --output=.private/local-finance.sql
```

Create a **new** D1 database and configure its ID in a separate deployment. Apply this repository's migrations, then restore the generated file:

```sh
npx wrangler d1 execute phooey-finance --remote --env production --file .private/finance.sql
```

This command must target the new database, never the original populated database. The generated file removes seeded categories, inserts the backed-up ordinary table data and rebuilds the full-text index. It does not restore active jobs, bank connections, or MCP grants; reconnect those afterward. Validate account counts, balances, ledger totals and saved tax plans before switching traffic.

A running D1 export blocks other database requests. The script explicitly selects ordinary tables because full database export does not support FTS virtual tables. See [D1 import/export guidance](https://developers.cloudflare.com/d1/best-practices/import-export-data/). D1 [Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/) is another whole-database recovery option; verify the target timestamp before applying it.

## Credentials

Rotate the administrator password by generating a bcrypt hash at cost 12 and setting `ADMIN_PASSWORD_HASH` through Wrangler secrets. Existing sessions then become invalid. Revoke MCP tokens separately in Settings if necessary. `ENCRYPTION_KEY` is a base64 32-byte AES key; changing it requires reconnecting SimpleFIN. Keep a secure separate copy when retaining encrypted connection records.

Production credential files generated by the setup script use owner-only permissions in ignored `.private/`. Do not reuse local demo credentials in production. A source archive is generated from an explicit allowlist and contains neither these files nor `.dev.vars`, R2 data or D1 files.

## Jobs and deployment

Settings shows job status, progress, provider errors and Retry for failed work. Queued/running jobs have leases; scheduled recovery re-enqueues expired work. Partial provider failures retain an earlier resume point instead of advancing the successful-history watermark. Replacing or disconnecting a bank cancels old-generation work.

Apply new D1 migrations before deploying the matching Worker. `npm run check` must pass first; it builds before integration tests. Cloudflare deployment rollback does not reverse schema migrations. Keep compatible schema changes and use backups/Time Travel for data recovery.
